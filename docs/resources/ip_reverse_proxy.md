# routeros_ip_reverse_proxy (Resource)
Manages a static RouterOS HTTPS-to-HTTP reverse proxy rule. Requires a router supporting /ip/reverse-proxy; SMIPS devices do not support it. Configure the reverse-proxy service listener and certificates separately.

The rule selects an exact SNI hostname, terminates HTTPS, and forwards plain
HTTP to an IPv4 or IPv6 backend. Wildcard routing is not supported. A wildcard
certificate can still cover several exact hostnames.

The `reverse-proxy` service owns the listener port and fallback certificate.
Keep its port distinct from an enabled `www-ssl` service, which also serves the
HTTPS REST API. DNS and firewall input rules must allow clients to reach the
listener. This resource does not change DNS, NAT or firewall rules.

Dynamic container-app rules remain owned by RouterOS and cannot be imported,
updated or deleted through this resource. Rule-level VRF is not exposed:
RouterOS 7.24.2 silently ignored it in native probes. Listener VRF is configured
through `routeros_ip_service`.

## Example Usage
```terraform
# Supply a certificate and private key already installed on the router.
# Port 8443 avoids the default www-ssl management port, 443.
resource "routeros_ip_service" "reverse_proxy" {
  numbers     = "reverse-proxy"
  port        = 8443
  certificate = "wildcard-cert"
  disabled    = false
}

resource "routeros_ip_reverse_proxy" "app" {
  sni         = "app.example.com"
  ip_address  = "192.0.2.10"
  port        = 8080
  certificate = "none" # Inherit the listener's certificate.
  comment     = "Application HTTP backend"

  depends_on = [routeros_ip_service.reverse_proxy]
}

resource "routeros_ip_reverse_proxy" "app6" {
  sni        = "app6.example.com"
  ip_address = "2001:db8::10"
  port       = 8080

  depends_on = [routeros_ip_service.reverse_proxy]
}
```

## Schema

### Required

- `ip_address` (String) IPv4 or IPv6 address of the HTTP backend. DNS names are not supported.
- `port` (Number) Backend TCP port. RouterOS forwards plain HTTP even when this is 443.
- `sni` (String) Exact TLS Server Name Indication hostname. Wildcard routing is not supported.

### Optional

- `certificate` (String) Certificate name for TLS termination. Use none to inherit the reverse-proxy service certificate.
- `comment` (String)
- `disabled` (Boolean)

### Read-Only

- `dynamic` (Boolean) Configuration item created by software, not by management interface. It is not exported, and cannot be directly modified.
- `id` (String) The ID of this resource.

## Import
Use the internal ID, an exact SNI hostname, or a selector that identifies one
static rule. Ambiguous and dynamic-only selections are rejected.

```shell
# Use the actual internal ID shown by /ip/reverse-proxy print as-value.
terraform import routeros_ip_reverse_proxy.app '*1'

# Alternatively select one static rule by its exact SNI.
terraform import routeros_ip_reverse_proxy.app 'sni=app.example.com'
```

Configuration-driven imports use the same selectors:

```terraform
import {
  to = routeros_ip_reverse_proxy.app
  id = "sni=app.example.com"
}
```

Match the resource configuration to the existing rule before applying the plan.
